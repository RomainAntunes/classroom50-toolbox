# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A tray app for [Classroom 50](https://github.com/foundation50/classroom50) students, in the spirit of JetBrains Toolbox. It runs from the macOS menu bar, the Windows notification area and the Linux tray. It:

1. Installs prerequisites: git, GitHub CLI (`gh`), and the `gh student` extension (`foundation50/gh-student`).
2. Discovers and tracks Classroom 50 assignment repos: due dates, submission state, grades.
3. Runs student actions: accept, clone, submit, and open in an editor, terminal or file manager.

The first release is for students only. Keep the domain layer role-agnostic so a teacher mode (`gh teacher`) can be added later without a rewrite.

- Repo: `github.com/RomainAntunes/classroom50-toolbox`. License: GPL-3.0, the same as Classroom 50.
- Status: tray, popover, tool detection and install, persisted settings, in-app sign-in, the merged project list (GitHub discovery, editor and folder scan with git status, Pages manifests), grades, Feedback PR activity, unmerged-branch detection, unaccepted assignments, notifications, the tray badge, and accept, clone and submit from the app are done.

## Stack and decisions (settled, don't re-litigate)

- **Tauri v2.** The Rust core lives in `src-tauri/`, and the UI is **Svelte 5 + TypeScript** (Vite) in `src/`. Performance matters: keep the webview bundle small and do the work in Rust, not JS.
- **Native look per OS through theming, not a cross-platform skin.** macOS gets vibrancy/blur and SF system fonts, Windows 11 gets Mica plus Fluent spacing and controls, and Linux follows GNOME/libadwaita (and respects KDE). Choose the theme from the platform at runtime and follow the system light/dark setting. The main surface is a popover-style window anchored to the tray icon, not a normal app window.
- **Auth reuses gh.** Run `gh student login` (which requests `admin:org read:org repo workflow`), then read the token with `gh auth token`. There is no separate OAuth app, and the app never stores its own token copy.
- **Installs go through the OS package manager.** That means Homebrew (macOS), winget (Windows) and apt/dnf/pacman (Linux), followed by `gh extension install foundation50/gh-student`. Upgrades use `gh extension upgrade gh-student`. Elevation (sudo/UAC) must be explicit and user-initiated.
- **Alerts:** native OS notifications (approaching due dates, a new grade, feedback, new assignments, a teammate's push), a tray badge for a teammate's push only, and autostart at login (launch hidden).
- **Release:** a GitHub Actions matrix builds dmg, msi/nsis, AppImage, deb and rpm when a PR merges into `main` with a new version, and attaches them to a draft GitHub Release. The owner publishes the draft by hand. The Tauri updater reads `https://github.com/RomainAntunes/classroom50-toolbox/releases/latest/download/latest.json`. Updater artifacts are signed with the Tauri key (kept in CI secrets). OS code signing (Apple notarization, Authenticode) is on hold until the toolbox has more users or funding; `docs/code-signing.md` has the plan (Developer ID for macOS, SignPath Foundation's free OSS signing for Windows) and `release.yml` the commented-out macOS secrets.
- **i18n:** English only, but every user-facing string goes through the i18n layer from the start.

## Classroom 50 contracts the app depends on

Classroom 50 has no server. All state lives in GitHub, so the app reads GitHub directly. Upstream publishes JSON Schemas in `schemas/` that are meant for GUI clients like this one. Validate against them instead of guessing field names.

- **`.classroom50.yaml`** (schema `repo-config-v1`) sits at the root of every accepted repo. Its required keys are `classroom` and `assignment`, and it may also hold `secret` (the unlisted-classroom key). It is **not** always there: `empty_repo` assignments commit no control files (`no_autograder` ones do get the marker, just no workflow), so a repo also counts when its name matches `<classroom>-<assignment>-<user or group>` (lowercase, longest slug wins, see `classroom50::assignment_for_repo`) for an assignment in its classroom's manifest.
- **`assignments.json`** (schema `assignments-v1`) is the published list of a classroom's assignments. It's public and needs no token: `https://<org>.github.io/classroom50/<classroom>[/<secret>]/assignments.json` (see `classroom50::assignments_url`). It holds due dates, release dates (`--available-from`), submission mode and group settings. A due date only marks work as **late** and never blocks it. Only the teacher's "Close submission" makes a repo read-only, so don't show a deadline as "locked".
- **Submissions:** depending on the assignment's mode, either every push to the default branch counts or only `submit/<UTC-timestamp>-<short-sha>` tags do (pushed by `gh student submit`). A teacher-named milestone tag pattern may also grade.
- **Grades:** each graded submission produces a non-draft **GitHub Release** tagged `submit/*` on the student repo, with a `result.json` asset (schema `result-v1`: `score`, `max-score`, `tests[{test-name, passed, score, max-score}]`, `datetime`, ...). GraphQL's `releaseAssets { url }` is a pre-signed download link, so it is fetched without a token, once per new tag.
- **Feedback PR:** opened at accept when the assignment enables it, titled `Feedback`, from the default branch into a `feedback` branch (which never counts as unmerged work). Teacher activity = its comments and reviews not written by the student.
- **Classroom teams:** each classroom has a secret student team `classroom50-<classroom>` whose description is a `classroom-team-v1` JSON record (`name`, `term`, `active`, `secret`, `pages_base_url`). It exists so a student can enumerate their classrooms without access to the private config repo. Staff teams are `classroom50-<classroom>-{teacher,hta,ta}`.
- **Web app:** `https://classroom50.org` (upstream `web/`). A student's page for an assignment is `/<org>/<classroom>/assignments/<assignment>/submission` (see `classroom50::submission_url`), and accepting is `/<org>/<classroom>/assignments/<assignment>/accept[?k=<secret>]` (`classroom50::accept_url`).
- **Group assignments** are GitHub Teams named `classroom50-group-<hash>-<n>`, owning `<classroom>-<assignment>-group-<n>`.
- Student CLI surface: `gh student accept <org> <classroom> <assignment> [--key] [--new-team [--team-name]]`, `submit` (no flags: it reads the key from `.classroom50.yaml`), `invite`, `team list|add`, `whoami`. Shell out to these for mutations instead of reimplementing accept or submit logic, which has many steps and changes upstream. Reading over the GitHub REST API is fine.
- Upstream reference: the wiki at `github.com/foundation50/classroom50/wiki`, especially `gh-student`, `How-Classroom-50-Works`, `Glossary` and `Autograding-Basics`.

## Project discovery (three sources, merged and de-duplicated by `owner/repo`)

1. **GitHub API:** the user's classrooms come from their classroom teams, plus any `.classroom50.yaml` seen. Their repos are those holding the marker file or named after one of the classroom's assignments.
2. **Local scan:** user-chosen folders (4 levels deep) and, unless the `scanEditorProjects` setting is off, the folders JetBrains IDEs and VS Code (and forks) opened recently, their parent folders and the IDEs' default `~/IdeaProjects`-style folders (`editors.rs`). A clone counts when it holds `.classroom50.yaml` or its GitHub origin matches an assignment repo. This gives local state (uncommitted changes, commits not yet submitted). The home dir itself is never walked: on macOS touching `~/Documents`, `~/Desktop` or `~/Downloads` raises a permission prompt. When a repo is cloned twice, the clone whose `.git/index` changed last is shown.
3. **Clones made by the app** (accept or clone), registered in `clones.json` (app config dir, so clearing the cache keeps it) when they're created and read as a single repo each scan. A plain `git clone` is picked up by source 2 once the folder is watched.

Remote data (due dates, releases) is cached locally. Refresh it on a timer and on tray open, and respect GitHub rate limits through conditional requests (ETags). The app never runs `git fetch` or anything else that writes to a clone: "new commits on GitHub" is found by checking whether GitHub's head commit exists locally (`git cat-file -e`).

## Commands

```sh
pnpm install
pnpm tauri dev                     # run the app (Vite on :1420 + cargo run)
pnpm tauri build                   # release bundles for the current OS
pnpm lint                          # prettier --check + svelte-check
pnpm format                        # prettier --write
cd src-tauri && cargo fmt && cargo clippy --all-targets -- -D warnings
cd src-tauri && cargo test                       # all Rust tests
cd src-tauri && cargo test parses_github_remotes  # single test (name filter)
```

`cargo build` and `cargo clippy` embed the built frontend through `generate_context!`, so run `pnpm build` once on a fresh checkout before using cargo directly.

The dev build is tray-only (no Dock icon, starts hidden). Open it from the tray icon, or launch the binary a second time: the single-instance plugin shows the popover.

## Layout

- `src-tauri/src/lib.rs` wires the plugins, managed state, tray and popover setup, and the command list.
- `commands.rs` is the IPC surface. Each command has a typed twin in `src/lib/api.ts`, and the two must stay in sync because Rust serializes with camelCase.
- `error.rs` holds the one `Error` enum, which crosses IPC as `{ kind, message }`.
- `process.rs` is the only place that spawns programs. It adds the usual install dirs to PATH, because a Finder-launched app has no `/opt/homebrew/bin`. It also sets `GH_PROMPT_DISABLED` and hides console windows on Windows.
- `platform/{macos,windows,linux}.rs` implement the same functions (install command, extra PATH dirs, open terminal) and are selected with `cfg(target_os)`.
- `tools.rs` detects and installs git, gh and gh-student, updates gh-student (`gh extension upgrade gh-student`; git and gh are left to the package manager), and reads gh's auth. The main page shows a Setup section only while a tool is missing; Settings always has a Tools section with versions, Install and Check again; Update appears only when `gh extension upgrade --dry-run` reports a newer gh-student. Installs and updates show an indeterminate bar (no progress is reported).
- `accounts.rs` lists gh's github.com accounts (`gh auth status --json hosts`), switches with `gh auth switch` (gh's global setting, so the terminal follows) and serves avatars as `data:` URLs, downloaded from `github.com/<login>.png` (the avatar CDN, not the API) at most weekly into `avatars/` in the app cache dir. The footer shows the active account and a native menu to switch or add one (the add path reuses the device flow).
- `login.rs` runs `gh auth login --web` with no TTY. gh prints the one-time code and the device URL on stderr, which are parsed and emitted as `login-device-code`. The browser takes focus and hides the popover, so the UI reports success through a system notification.
- `settings.rs` stores `settings.json` in the app config dir, written atomically. A corrupt file is moved to `.bak`. On first run (no file) the login item is registered. `apply_launch_at_login` skips this in debug builds, and `get_settings` reports the OS's real login-item state.
- `classroom50.rs` holds the typed upstream contracts, Pages URLs and web app URLs. `discovery.rs` is the local scanner. `editors.rs` reads the editors' recent-project lists (JetBrains `recentProjects.xml`, `file://` URIs in VS Code's `storage.json` and `state.vscdb`) from `platform::editor_config_dirs()`; it only reads them.
- `github.rs` is the read-only GitHub layer: GraphQL with typed rate-limit errors, and `HttpCache`, which revalidates GETs with ETags and persists bodies in the app cache dir. The token is read from `gh auth token` per sync and never stored.
- `projects.rs` owns the merged project list. A sync lists every repo the user can see (cheap query), reads the user's classroom teams, re-reads `.classroom50.yaml` and the newest `submit/*` tag only for repos whose `pushedAt` changed (aliased batches of 25; bigger batches time out), runs `git status` in each local clone, fetches each classroom's manifest once and computes `pending`. After identifying the assignment repos, a sync re-reads just those with the status fragment (`status.rs`: branches compared with `HEAD`, the newest graded release, the Feedback PR), then compares each clone with GitHub (`git for-each-ref --no-merged`, `git cat-file -e`). The discovery cache is `repos-v2.json` in the app cache dir. A background tick every 30 s decides what is due (`projects::cadence`, from the nearest deadline of unfinished work): a status check (`Mode::Status`, small batches of 3 repos, at most 4 requests in flight) every 1 min in a deadline's last 3 h, every 2 within a day, every 5 within a week, else every 15 with the full sync hourly instead of every 15 min. Waking from sleep (wall clock jumping ahead of the monotonic one) syncs after 5 s. A connect or timeout failure is `Error::Offline`: background syncs stop and the tick only probes `api.github.com:443` over TCP (no HTTP request) until it answers. A status check also runs when the popover opens (at most every minute) and right after a push or pull (the watcher sees `.git/refs/remotes` or `FETCH_HEAD` change; then again after 1 and 3 min for the grade, one round at a time). Background syncs never run while GitHub asks to back off (`retry_after`, kept across restarts) or while under 10% of the GraphQL budget is left; class manifests are re-downloaded at most every 10 min. The last snapshot and stats are saved to `snapshot.json`, so a restart shows everything at once, only rescans the disk and doesn't sync GitHub before it's due. A status check first compares `gh config get user` (local) with the cached login and turns into a full sync after `gh auth switch`; `alerts.json` starts a new baseline for the new account. Only syncs the user started (`SyncProgress.foreground`) show the spinner and bar. The result goes out as `projects-updated`; progress goes out as `sync-progress` (the titlebar bar). Concurrent refreshes share the sync in flight. `refresh_local` rescans the folders only and reuses the last GitHub data (no API call).
- `alerts.rs` compares each snapshot with `alerts.json` (app cache dir) and emits `notify` notices (deadline reminder at the tightest reached `notifyHoursBefore`, new grade, new Feedback PR comments, newly published assignment, a teammate's push, a moved deadline, submissions closed) that the layout words through i18n and sends; the first snapshot is a silent baseline. It also keeps the `unseen` ids (a dot in the list, cleared when the popover hides). The tray badge (`tray::set_badge`, a dot drawn into the icon) is for one thing only: a teammate pushed and the popover hasn't been opened since. `src/lib/notices.ts` words and sends the notices; dev builds get a Developer section in Settings that sends a sample of each kind and lights the badge (`preview_badge`). In `tauri dev` macOS shows them with Terminal's icon (the plugin borrows `com.apple.Terminal` because the binary isn't bundled); bundled builds use the app's.
- `clones.rs` clones with `gh repo clone owner/repo <cloneFolder>/<repo>` (gh's credentials, so private repos need no git setup) and keeps the registry of app-made clones. The clone folder is the `cloneFolder` setting, asked on the first clone (`src/lib/clone.ts`); "Clone to…" in a row's menu picks another and remembers it. An existing target folder is `Error::PathExists`.
- `student.rs` runs the `gh student` writes (accept, submit) with a timeout, from a non-git cwd for accept. It keeps the CLI's own error line (after `gh-student: `) as `Error::Student`, and a team assignment with no group as `Error::NeedsTeam`. Accept never prompts, so `src/lib/accept.ts` asks first (public repo, group rules), offers to found a group on `needsTeam`, then offers to clone. Upcoming (`availableFrom` ahead) and locked assignments can't be accepted from the row. Submit doesn't commit locally: it snapshots the working tree (tracked files plus untracked ones that aren't ignored) and pushes it as a new commit on top of GitHub's head, which undoes changes made only on GitHub, so `src/lib/submit.ts` warns when GitHub is ahead, lists new files, refuses deletions not staged with `git rm` (submit would fail on them) and repos without a marker. Afterwards the clone is one commit behind, and `refresh_after_push` runs because no local ref moved. `process.rs` sets `GIT_TERMINAL_PROMPT=0` so a push without credentials fails instead of hanging.
- `watch.rs` watches what each sync reports (`projects::watch_targets`): watched folders and known clones recursively, the editors' recent-project files and project folders non-recursively (for those folders only a child being created, removed or renamed counts). It runs `refresh_local` 2s after the last write, so a `git clone`, commit, edit or a project opened in an editor shows up without a GitHub request. Reads and `node_modules`/`target`/dot-dirs other than `.git` (judged below the target) are ignored. It is only rebuilt when the targets change.
- `tray.rs`, `popover.rs` and `updater.rs` handle the tray icon and menu, the anchored window (hide on blur, vibrancy or Mica) and self-update. A native dialog steals focus and would hide the popover, so every dialog-plugin call and every native context menu (`Menu.popup()`) in the UI is wrapped in `withDialog()` (`src/lib/api.ts`), which pins the popover while it is open. The webview's own context menu is disabled outside text fields.
- The Settings footer shows the version and the commit it was built from (`__COMMIT__`, injected by `vite.config.js`, `-dirty` when the tree had changes) with links to GitHub.
- `src/lib/settings.svelte.ts` holds the shared settings state. Rust is the source of truth: write through `saveSettings`, never mutate locally. It also migrates the v0.1.0 `localStorage` folder list.
- `src/lib/theme/theme.css` holds the semantic tokens plus a skin per `data-os`. Components use tokens only.
- Icons: `assets/icon.svg`, `assets/icon-small.svg` (heavier strokes, used at 44px and below) and `assets/tray.svg` are the sources. Never edit `src-tauri/icons/` by hand; run `scripts/build-icons.sh` (macOS only, needs `rsvg-convert` and ImageMagick).
- `src/lib/i18n` is a flat `en.json` read through `t(key, params)`. New strings go there.
- The updater public key is in `tauri.conf.json`. The private key and its password are in `~/.tauri/classroom50-toolbox.key{,.password}` locally and in the CI secrets `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Losing them strands existing installs on their current version.
- Release: run `pnpm bump X.Y.Z` in the PR, which updates `package.json` (read by `tauri.conf.json`) and `Cargo.toml`. On merge, `release.yml` sees that `vX.Y.Z` has no release yet, builds every platform and creates a draft release with `latest.json`, tagging the merge commit. Merges without a bump build nothing. Publishing the draft ships the update. Don't push tags by hand.

## Conventions

- Keep platform-specific code (package managers, tray behavior, autostart, opening editors) in `platform/`, one file per OS exposing the same functions. The UI never branches on OS for behavior, only for theming.
- Every call to `gh` or `git` goes through one Rust process wrapper that captures stderr and exit codes and returns typed errors. Never build shell strings; pass arguments as a vector.
- Rust owns all state and I/O. Svelte only renders and invokes typed Tauri commands, and receives events for progress and refreshes.
- Tauri permissions are allow-listed in `src-tauri/capabilities/default.json`. A plugin API called from JS needs its permission added there.
- Don't use em-dashes in code, comments or UI strings.
- **Dev builds never write to GitHub.** The owner develops against their real classes, so `process::checked_args` refuses `gh student submit|accept|invite|team add` and `git push` under `debug_assertions`. Never weaken or bypass this, and never run those commands by hand while testing. Test the write paths with unit tests or a throwaway repo the owner sets up.
